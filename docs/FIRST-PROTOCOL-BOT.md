# أول بوت بروتوكول في MIR: Protocol Claim Watcher

8 November 2026 — MIR is independent, built by WADJ Studio. LXR remains its internal analytics engine.

**الحالة: نسخة أولى تعمل بالقراءة فقط، بقائمة مراقبة محدودة واكتشاف تجريبي من أحداث المطالبات السابقة. ليست بوت تنفيذ مالي، ولم تثبت ربحًا حقيقيًا.** لا تحتاج عميلًا تجاريًا؛ فرضية الدخل هي رسوم يدفعها البروتوكول مقابل المطالبة بجوائز الفائزين. راجع [نتيجة الاكتشاف الحي وحدود العينة](PROTOCOL-BOT-DISCOVERY.md).

## لماذا PoolTogether أولًا؟

راجعنا [دليل المطالبة الرسمي](https://dev.pooltogether.com/protocol/guides/bots/claiming-prizes/) و[عناوين Base الحالية](https://dev.pooltogether.com/protocol/deployments/base/). توجد آلية رسوم موثقة ومكوّن محاسبة داخل MIR بالفعل. الاختيار مبني على ملاءمة البدء وإعادة الاستخدام، وليس دليلًا على أن المجال قليل المنافسة أو مربح لنا.

يقارن البوت حالة الجوائز والرسوم عند بلوك واحد، بدل استنتاج فرصة من حجم جوائز البروتوكول الإجمالي. المكافأة المعروضة رصيد مشروط بنجاح المطالبات؛ ليست تحويلًا ماليًا. محاسبة التحويلات الفعلية منفصلة في [بوابة محاسبة البروتوكول](PROTOCOL-WORK-ACCOUNTING.md).

## ما تم بناؤه وتشغيله

- تحقق من Base، وجود كود للعقود، ارتباط Claimer بالـPrizePool وهوية WETH و18 decimals. يسجل SHA-256 للكود المرصود، **ولا يدّعي مطابقته لبناء مدقق**.
- قراءة hash-pinned مع `requireCanonical`؛ وإعادة فحص رأس البلوك بعد الجمع. يستخدم بلوكًا حديثًا غير نهائي، ولذلك يظل احتمال إعادة التنظيم قائمًا.
- فلترة الترشيحات المحددة: رقم السحب، tier، prize index، `isWinner` و`wasClaimed`؛ مع الاحتفاظ بأسباب الرفض.
- تجميع المطالبات غير المنفذة حسب vault وtier، وقراءة `computeTotalFees` مباشرة من العقد. لا نعيد تنفيذ منحنى تسعير الرسوم من الصفر.
- حسابات BigInt بوحدة WETH wei لسيناريو التكاليف الأساسي والمضاعف. أي تكلفة مجهولة تجعل الصافي مجهولًا. لا نفترض ثبات قيمة الدولار أو احتمال الفوز بالمنافسة.
- حفظ سجل الطلبات ونتائجها بهوية محتوى، ونشر الملف كاملًا بصورة ذرية. تعيد الواجهة تشغيل التحقق من المدخلات؛ لا تثق في حقل ربح محفوظ.
- إدراج البوت في MIR Lab وواجهة `GET /api/bots/pooltogether`. `GET /api/bots` يعرضه بجانب المسارات الحالية. HTTP لا يبدأ جمعًا أو يحفظ نتائج؛ يقرأ الأدلة فقط ويرفض الكتابة.
- لا توجد طريقة توقيع أو إرسال معاملات. المواصل يجيز فقط طلبات قراءة محددة إلى عقود محددة؛ لا محافظ أو مفاتيح أو موافقات أو استدعاءات `claimPrizes`.

## التشغيل

من جذر المشروع، باستخدام Node 22 أو أحدث؛ لا توجد حزمة جديدة مطلوبة:

```powershell
npm run bot:pooltogether
npm start
```

الأمر الأول يشغل **عينة وهمية صريحة** ويحفظ دليل اختبار محليًا. افتح `/lab.html` على الخادم المحلي. لو توجد قراءة عامة محفوظة، تعرض الواجهة أحدث قراءة عامة، حتى لو فشلت؛ لا تستبدلها بالعينة لتبدو ناجحة.

قراءة عامة واحدة، دون أي إعادة محاولة تلقائية:

```powershell
npm run bot:pooltogether:live
```

المصدر هو [Base PublicNode](https://base.publicnode.com/)، الذي ينشر عنوانه العام `https://base-rpc.publicnode.com`. لا يتم استخدام المصادر التي رفضت الوصول سابقًا أو تجاوز تحدياتها.

الإعداد الافتراضي في `config/pooltogether-watchlist.json` يحتوي **قائمة يدوية فارغة وتكاليف مجهولة**، ويبحث آخر 128 بلوك عن مشاركين في مطالبات سابقة. إذا وجدهم، يضيف ترشيحات محدودة ويختبر الفوز وحالة المطالبة من جديد؛ الجائزة القديمة لا تصبح فرصة جديدة تلقائيًا. هذه ليست قائمة كل الحسابات المؤهلة. لاستخدام قائمة يدوية أو سياسة اكتشاف مختلفة ضمن الحدود، استخدم ملفًا محليًا موثق المصدر:

```powershell
node apps/monitor/pooltogether.mjs --live --watchlist path/to/verified-local-watchlist.json
```

لكل seed: `vault` و`winner` عنوانان، و`tier` و`prizeIndex` عددان صحيحان. الحد 16 seed. يجب أن تكون العناوين lowercase؛ لا تضع مفاتيح أو أسرارًا في الملف. تعريف قائمة مرشحين لا يعني إثبات صلاحية vault أو hooks أو إمكانية التنفيذ.

التكاليف السبعة بوحدة wei: التنفيذ، L1، رسوم المشغّل، السحب/فك التغليف، المحاولات الفاشلة، المعالجة والبيانات، ونصيب الصيانة. كلها افتراضات محلية لكل batch، وليست تقدير غاز موثقًا أو تكاليف مقاسة. تشمل الربحية الدورية لاحقًا فترات عدم وجود مهام أيضًا. السيناريوهات مستقلة؛ لا تجمع مكافآت batches منفصلة كأن تسعيرها سيظل ثابتًا بعد كل مطالبة.

الحدود: 96 طلبًا، 60 ثانية لقبول الطلبات، 8 ثوانٍ كحد أقصى للطلب ضمن الميزانية، 256 KiB للاستجابة و2 MiB إجماليًا، بلا retries أو redirects. يعاد تصنيف الأدلة التي يزيد عمر بلوكها على دقيقتين كقديمة. لا توجد جدولة خلفية.

## نتيجة التجربة الحالية

- العينة الوهمية: ثلاثة ترشيحات؛ واحد غير مطالب به، وواحد سبق تنفيذه، وواحد ليس فائزًا. رسوم افتراضية 100 وتكاليف افتراضية 30 تعطي 70 ثم 40 مع المضاعفة. هذه **قيم اختبار بالـwei، ليست دخلًا أو فرصة فعلية**.
- هوية العينة: `c9b8c4f2874ca63d2f784cdff4ea364019647df7545a85dab39b746cd83547b4` في `data/bots/pooltogether`.
- المصدر العام أجاب عن الشبكة والرأس، ثم تعذر طلب قراءة العقد التالي. سجلنا 3 طلبات و25,777 بايت استجابة، بلا retries. هوية الدليل: `565e0b0c6340b93db9fdcf7d7fd34ec258291f8353dbc3d65aa1ef878d76346f`. الحالة `source-unavailable`؛ لا توجد نتيجة أسعار أو مكافآت حية معتمدة.
- أثناء الاختبار أصلحنا مقارنة وقت البلوك ببداية الجمع: المقارنة الحية تتم عند استلام الرأس. حالات البلوك القديم أو المستقبلي تحفظ كأدلة مرفوضة دون مكافآت. تشغيل أولي رفض التوقيت قبل هذا الإصلاح؛ لا ننسب إليه دليل معاملات محفوظًا.
- فحص محاسبة الرسوم، الرفض، دقة الأعداد الكبيرة، التلاعب بالملفات، الشبكة الخاطئة، تغيير البلوك، الميزانية، حظر المعاملات وHTTP متضمن في الاختبارات. نقلنا مساحة الاختبارات المؤقتة داخل المشروع عند امتلاء قرص C، دون حذف ملفات المستخدم.
- النتيجة النهائية: **92 اختبار Node ناجح**، منها 13 خاصة بالعامل الجديد. جرى فتح MIR Lab وفحص ظهور البوت وحالة المصدر غير المتاح بعد اكتمال تحميل التقارير.

الأدلة الخام محلية ومُتجاهلة في Git؛ الكود والإعدادات والاختبارات والعينة المولّدة داخل المصدر متاحة لإعادة التشغيل. هوية المحتوى تمنع التعديل الصامت، لكنها ليست إثباتًا مستقلًا لصدق مزود RPC.

## خطة الوصول إلى بوت دخل قابل للتقييم

| المرحلة | الحالة / شرط الانتقال |
|---|---|
| Worker للقراءة، التكاليف المشروطة، التخزين والعرض | منفذ ومختبر محليًا؛ اكتملت قراءات عامة لاحقة. عينة الأحداث الحية كانت فارغة، ولا يوجد مرشح مربح مثبت |
| بيانات مرشحين حقيقيين | أضيف bootstrap من مشاركين في مطالبات سابقة. المتبقي فهرس حسابات TWAB/أحداث قابل للاستئناف، مصدر وعناوين vault موثقة، وتغطية أوسع دون إخفاء الفجوات |
| تحقق صلاحية التنفيذ | تحقق vault→claimer، مصدر bytecode، وفحص hooks؛ محاكاة المطالبة على fork عند البلوك نفسه مع الفشل الجزئي |
| دليل اقتصادي تاريخي | تحويلات مكافآت فعلية، دفتر credit، كل المحاولات والتكاليف؛ لا نعتبر أرباح بوت آخر حصة مضمونة لنا |
| متابعة ورقية أمامية | سياسة ثابتة لمدة 30 يومًا على الأقل؛ قياس عمر الإشارة، الفقد للمنافسين، الغاز والفترات الخالية، وصافي موجب بعد التكاليف ومضاعفتها |
| تنفيذ مالي | مرحلة منفصلة خارج التفويض الحالي؛ لم تُبنَ أو تُشغّل |

لا يتم ترقية أي نتيجة بمجرد وجود quote موجب أو محاكاة ناجحة. لا توجد حتى الآن مكافآت مستلمة أو سياسة مربحة مثبتة لـMIR. نحتفظ بـLiquity والتصفية ومزادات السحب كبدائل بحث منفصلة إذا لم يدعم الدليل مسار المطالبة.

## المصدر والرخص وإعادة الاستخدام

`tools/research/pooltogether_reads.py` يولّد تسعة تعريفات قراءة ومرجع ABI encoding من الحزمة الرسمية المثبتة سابقًا، بعد التحقق من SHA-256 `6f264ba14cbe0fca4df45f7ebfd842d334d376e4afc9ef309510257c6f9f1293`. يستخدم `eth-abi==6.0.0` و`eth-utils==6.0.0` في البيئة المعزولة الموجودة؛ لا تثبيت جديد. يمكن تشغيله دون شبكة عند وجود الأثر الخام المحفوظ.

المصدر التنفيذي للعقد يحمل MIT؛ لم ننسخ تنفيذ العقد أو بوت طرف ثالث. استخدمنا بيانات ABI factual وتعريف ERC20 decimals، وكتبنا العامل والمواصل والاختبارات داخل MIR. تطابق selector/encoding يُفحص بمرجع مستقل من eth-abi؛ هذا ليس اختبار fork أو مطابقة live bytecode. تظل رخص المشروع وتبعياته المراجعة كما هي؛ لم نختر رخصة جديدة نيابة عن المالك.
