# أدوات Ethereum المناسبة لـ MIR

تاريخ الفحص: 2026-11-08. الهدف: دعم أول بوت يتقاضى حافزًا بروتوكوليًا، عبر القراءة والتحقق والمحاكاة الورقية. لا يوجد إثبات ربح حتى الآن.

## القرار

نستخدم الأدوات الموجودة، ونحل فجوة بيانات Ethereum قبل توسيع البنية. دليل [Ethereum Builder Resources](https://ethereum.org/developers/tools/) نقطة اكتشاف، وليس تزكية أمنية أو ضمان إتاحة أو عائد. راجعنا مصادر المشاريع المختارة مباشرة؛ لم نشغّل تعليماتها تلقائيًا.

| المورد | ما يفيد MIR | الحالة والحدود | المصدر |
|---|---|---|---|
| Foundry / Anvil | محاكاة EVM محلية قابلة للتكرار | Anvil v1.8.6 مسجل محليًا مع SHA-256 في tools/evm/anvil-resource.json. لا تثبيت مكرر. الـfork يحتاج حالة شبكة متاحة؛ عقدة التطوير لا تثبت عائدًا حقيقيًا. | [المصدر](https://github.com/foundry-rs/foundry) |
| 1RPC | مرشح مصدر قراءة عام مستقل | الوثائق تنشر public.1rpc.io/eth بدون مسار مفتاح. هذا توثيق إتاحة عامة، وليس إثبات أن الطلب يعمل من بيئتنا أو يدعم كل طرقنا. لم تكتمل تجربة طلب جديدة: تشغيل العملية محليًا أعاد spawn EPERM قبل إرسالها. لا تُسجل كـHTTP 403 من 1RPC. | [الشبكات](https://docs.1rpc.io/overview/supported-networks) |
| Ponder | فهرسة أحداث بعقود وعناوين محددة، ثم GraphQL/SQL | مرشح لاحق؛ راجعنا المصدر، ولم نثبته أو نختبر دمجه. MIT بحسب المستودع. إعداداته تحتاج RPC وتخزينًا؛ ليس بديلًا لمصدر الحالة. | [المستودع والإعداد](https://github.com/ponder-sh/ponder) |
| Multicall3 | تجميع قراءات العقود لتقليل الطلبات | مرشح تحسين بعد صحة القراءات الفردية. لم يُدمج. يلزم تثبيت هوية الشبكة والبلوك والتحقق من bytecode للعنوان واختبار اختلاف msg.sender وفشل كل نداء. لا معاملات أو approvals أو نشر عقد. | [المصدر](https://github.com/mds1/multicall3) |
| Helios | تقليل الثقة في نتائج مزود RPC عبر عميل خفيف | راجعنا المتطلبات، ولم نثبته. يحتاج Execution RPC يدعم eth_getProof ومصدر consensus/checkpoint موثوقًا؛ ليس مصدر حالة مستقلًا يحل رفض الوصول. | [المتطلبات](https://github.com/a16z/helios#usage) |
| Slither | تحليل Solidity وصلاحياته ومساراته قبل الاعتماد على بروتوكول | مرشح تحليل معزول عند اختيار عقود محددة؛ لا تثبيت جديد في هذه الجولة. رخصته AGPL-3.0 بحسب المصدر، فلا نفترض MIT ولا ننسخ تنفيذه. تقريره لا يثبت أمان عقد أو جدوى اقتصادية. | [المصدر والرخصة](https://github.com/crytic/slither) |

الترخيص أعلاه مراجعة أولية للمصدر الحالي؛ قبل إدخال أي مورد جديد يلزم إصدار/commit ثابت، رخصة وإشعارات تبعيات، lockfile، حدود صلاحيات، واختبار خاص بالحاجة. هذه ليست قائمة حزم مثبتة.

## أدوات الوكلاء

راجعنا قسم MCP والمهارات في الدليل. أدوات المحافظ والتوقيع والدفع والتداول ليست ضمن احتياجات المرحلة الحالية. وجود زر simulation قبل write لا يحول أداة مالية إلى أداة قراءة. لا أضفنا MCP جديدًا ولا عدلنا إعدادات Codex، ولا اعتبرنا وصف دليل خارجي صلاحية جديدة.

يمكن بحث مساعد للمواصفات لاحقًا، لكن تفسير الوكيل لا يحل محل فحص ABI وحسابات صحيحة وإعادة تشغيل الأدلة. وكلاء الاستكشاف يحصلون فقط على واجهات قراءة محدودة وميزانيات طلبات، لا على client عام متعدد الصلاحيات.

## المسار العملي التالي

1. فحص مصدر عام موثق مستقل مرة واحدة: chainId ثم رأس بلوك حديث؛ بدون redirects أو مفاتيح أو إعادة محاولة عند منع الوصول. لا تدوير تلقائي حول المصادر المرفوضة.
2. إذا نجح، فحص دعم eth_getCode وeth_call المثبتين بـblockHash، وعلاقات عقود Liquity WETH الحالية وقراءات oracle والصفقات المفتوحة ضمن حدود الجامع الموجود. نجاح chainId وحده لا يجيز وصف المصدر بأنه صالح للمختبر.
3. حفظ raw transcript وهوية المصدر والبلوك والزمن وhash المحتوى، ثم إعادة الحساب باستخدام verifier الموجود. البيانات الناقصة تبقي النتيجة مجهولة.
4. محاكاة محلية على حالة أصلية متاحة، وتقدير حافز التصفية وتكلفة النجاح والفشل وزمن المنافسة. تكلفة المتابعة وفترات غياب العمل تدخل الاقتصاديات؛ الحافز المشروط ليس دخلًا متكررًا مثبتًا.
5. إضافة الفهرسة أو التجميع فقط إذا قياس المدخلات نفسها أظهر حاجة حقيقية. لا نبدأ عقدة كاملة أو نثبّت frameworks إضافية قبل تقدير القرص والموارد.

## ما تم وما لم يتم

- تم اختيار طبقات وأدوات لها استخدام محدد بدل تثبيت كتالوج كامل.
- لم تُثبت حزمة جديدة، ولم تتغير المصادر المرفوضة أو إعدادات المحافظ.
- لم نحصل في هذه الجولة على snapshot جديد لمراكز Liquity أو قياس gas حقيقي أو ربح صافٍ.
- القراءة عبر lean-ctx تعطلت بسبب امتلاء قرص C؛ استخدمت قراءة ملفات مباشرة. تعذر تشغيل عملية الاختبار الجديدة بـEPERM، ولم يُنشأ سجل بيانات يدعي نجاحها. لم نحذف ملفات أخرى لتحرير المساحة.
- مكون الحساب الاقتصادي المحلي في [التجربة الاقتصادية](LIQUITY-ECONOMIC-EXPERIMENT.md) أُضيف واختُبر قبل هذا الاستكشاف: ستة اختبارات اقتصاد وسبعة اختبارات screen/replay نجحت. افتراضات التكلفة والمنافسة تظل مجهولة افتراضيًا.

الاختيار الحالي: جامع قراءة محدود → verifier وإعادة تشغيل → حساب اقتصادي → Anvil عند توفر الحالة → متابعة ورقية. Ponder وMulticall3 تحسينان مؤجلان؛ Helios طبقة تحقق محتملة. أي ترقية لنموذج تتطلب دليلًا مستقلًا موجبًا بعد التكاليف والضغط، لا مجرد زيادة الأدوات.
