## What changed

`pooltogether_accounting.py` reads supplied raw RPC receipt exports. It uses the
already reviewed `eth-abi==6.0.0` and `eth-utils==6.0.0` environment, rather than
implementing a new ABI decoder. No package was installed and no executor, wallet,
RPC transport, approval or signing capability is part of this accounting module.

`pooltogether-reference.json` contains six event schemas derived from the official
published Base deployment artifacts. PrizePool and Claimer versions are recorded
as published 1.0.0 deployments; the file does not certify live deployed bytecode,
token identity or decimals. Artifact checksums are:

- ABI: `6f264ba14cbe0fca4df45f7ebfd842d334d376e4afc9ef309510257c6f9f1293`.
- Configuration: `8b4bee822293d09677ed40e39bb15951706da0e754f8176b75f340e77329729b`.

The reference generator verifies those source bytes and deployment/event
associations before deriving topics. Only factual ABI metadata is included;
upstream executable contracts or bots were not copied or installed.

## Accounting facts from the official implementation

| Input | Treatment |
|---|---|
| `ClaimedPrize.claimReward` | Accrued reward credit; not a token receipt |
| `IncreaseClaimRewards` | Mirror of the same accrual; never added twice |
| Winner payout | Excluded from caller income |
| `AllocateRewardFromReserve` | Separate credit source; not claim income |
| `WithdrawRewards` | Reduces credit; match the preceding prize-token Transfer before counting cash |
| Withdrawal to PrizePool itself | Reduces credit without a cash transfer |
| Withdrawals funded by opening credit | Not all current-period earned income |
| Caught `ClaimError` | Failed inner work can exist inside a successful outer transaction |

Sources: [official PrizePool implementation](https://raw.githubusercontent.com/GenerationSoftware/pt-v5-prize-pool/main/src/PrizePool.sol),
[deployment ABI](https://raw.githubusercontent.com/GenerationSoftware/pt-v5-mainnet/main/deployments/base/contracts.json),
[Base configuration](https://raw.githubusercontent.com/GenerationSoftware/pt-v5-mainnet/main/config/base.json),
[Claimer implementation](https://raw.githubusercontent.com/GenerationSoftware/pt-v5-claimer/main/src/Claimer.sol).

The supplied inventory equation is opening reward credit + claim accrual + reserve
allocation − withdrawals = closing credit. Full supplied windows also check the
intermediate `available` balance exposed by withdrawals. Partial coverage cannot
establish that inventory equation.

Receipts and logs are checked for canonical ordering, consistent hashes, removed
logs, duplicates, ABI bounds and mirror consistency. A wrong token emitter cannot
confirm cash receipt. Costs count once per transaction, including withdrawal and
failed transactions. Missing L1/operator fees or unresolved payer attribution do
not become zero. Prize-token and native-gas units are kept separate.

transactions include a withdrawal, one reverted transaction and one inner claim

Those units are not silently equated with prize-token units. Net and MIR revenue
remain unknown. This demonstrates accounting behavior only.

## Generic ledger compatibility

`paid_work.py` now requires `rewardSemantics: "direct-token-transfer"`. An accrued
credit export is rejected there and must use protocol-specific accounting.
`conditionalCashFlowNetAtomic` states the quantity being calculated; legacy
`conditionalNetAtomic` remains the same cash-flow alias, not earned-profit proof.
The illustrative direct-transfer fixture was updated. Old reports remain intact.

## Live-data access result and decision

Two new independently documented public read surfaces were tried once each:

- Blockscout's public Base PrizePool log page: HTTP 403 with a Cloudflare challenge.
  Record: `data/paid-work-probe/f61cf921b45bd2b643705db68898becb873744e99833566ab2edf6d67b90ead2.json`.
- Base's official public RPC, `eth_chainId` only: HTTP 403.
  Record: `data/paid-work-probe/19bd7e23cdda03f4ff127773dccf4645d3669150fe16d851b1ae588920663fcf.json`.

No challenge, authorization requirement or blocked shell command was bypassed.
No paid/keyed provider was provisioned. A failed read is not an empty job queue.
References: [Base public network details](https://docs.base.org/get-started/connect-to-base),
[Blockscout API information](https://docs.blockscout.com/devs/blockscout-api).

Public aggregate protocol fee charts are not a substitute for caller receipts.
The [DeFiLlama V5 adapter](https://raw.githubusercontent.com/DefiLlama/dimension-adapters/master/fees/pooltogether-v5/index.ts)
classifies prize-token contributions as protocol fee activity; this does not
measure keeper cash income or their net margins.

Decision: retain PoolTogether as an unqualified hypothesis. Economic promotion is
paused until a permitted live source provides actual event/receipt/state evidence.
This does not pause the wider MIR research program. Before an observer can assess
opportunity capacity it needs complete coverage, prize-token identity, balance and
shutdown/eligibility reads, failed-attempt history and independently checked costs.
Before claiming recurring profit it also needs timing/competition measurements
and frozen forward outcomes. Historical payouts to other operators are not MIR
revenue. No scheduler or market-monitoring service was started by these commands.
